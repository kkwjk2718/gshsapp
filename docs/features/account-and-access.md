# 계정 및 접근 기능 명세

이 문서는 로그인, 회원가입, 토큰 발급, 개인화, 알림, 오류 신고처럼 계정과 접근 제어에 관련된 기능을 정리합니다.

## 1. 로그인

- 목적: 사용자 역할과 개인화 기능 접근을 가능하게 합니다.
- 대상 사용자: 학생, 졸업생, 교사, 방송부, 관리자
- 진입 경로: `/login`
- 핵심 동작:
  - 아이디/비밀번호 로그인
  - 존재하지 않는 계정에도 더미 비밀번호 검증을 수행하여 계정 존재 여부 타이밍 차이를 줄임
  - 실제 비밀번호 검증 실패만 제한 횟수에 포함하고, 이미 차단된 요청은 잠금 시간을 연장하지 않음
  - DB의 현재 역할과 `sessionVersion`이 JWT claim과 정확히 일치할 때만 회원 기능 허용
  - 비밀번호 또는 역할 변경 시 기존 세션 폐기
  - 로그아웃은 GET 쿠키 변경이 아닌 POST Server Action으로 처리하며 로컬 경로만 허용
- 관련 관리자 기능: 사용자 계정 관리, 토큰 발급
- 회귀 시 주의할 점:
  - 테스트/운영 도메인 리다이렉트가 섞이면 안 됨
  - 비로그인 상태에서 상단 테마 토글은 보여도, 계정 메뉴는 로그인 상태에 맞게 보여야 함

## 2. 토큰 기반 회원가입

- 목적: 초대 토큰을 받은 사용자만 계정을 생성하게 합니다.
- 대상 사용자: 학생, 졸업생, 교사, 방송부, 관리자
- 진입 경로: `/signup#token=...` 또는 `/signup`에서 토큰 직접 입력. URL query의 토큰은 받지 않음
- 핵심 동작:
  - 토큰 검증
  - 역할/기수 검증
  - 비밀번호 설정과 계정 생성
  - 가입, 본인 변경, 관리자 초기화, 포털 비밀번호에 12문자 이상·UTF-8 72바이트 이하의 중앙 정책 적용
  - 토큰 사용 처리
  - 신규 토큰은 256비트 CSPRNG 값의 SHA-256 해시만 DB에 저장하고 원문은 최초 다운로드 또는 메일 발송 시 한 번만 제공
  - 메일 발송 토큰은 수신 이메일과 학생의 경우 학번에도 결합하며, 가입 시 같은 트랜잭션 안에서 결합 정보를 확인
  - 조건부 1회 claim을 계정 생성보다 먼저 수행하여 동시 가입에서도 계정 하나만 생성
  - 입력 검증 후 식별자/네트워크별 LRU 시도 제한과 토큰 사전 조회를 bcrypt보다 먼저 수행하며, 학교 NAT를 고려해 네트워크 한도를 더 높게 적용
  - 비밀번호 해시 계산 전에 만료·사용·수신자 결합을 저비용 조회로 검증하고, 실제 생성 시에는 다시 원자적으로 claim
  - 브라우저는 fragment 토큰을 읽은 즉시 주소 표시줄과 history에서 제거하므로 서버·프록시 요청 로그와 Referer에 원문 토큰을 싣지 않음
  - 발급 후 7일이 지난 `InviteToken`은 배부 이력의 참조를 분리한 뒤 제한된 배치로 삭제
- 데이터 저장:
  - `InviteToken`
  - `User`
- 관련 관리자 기능: `/admin/tokens`
- 회귀 시 주의할 점:
  - 토큰 발급 후 가입 단계는 토큰을 직접 배부할 때와 동일해야 함
  - 토큰 만료 규칙과 사용 처리 규칙을 바꾸지 않음

## 3. 토큰 배부 포털

- 목적: 학생 대상 토큰 메일 발송을 관리자가 켰을 때만 공개적으로 수행합니다.
- 대상 사용자: 학생용 토큰을 요청하는 사용자, 관리자
- 진입 경로: `/signup/request`
- 핵심 동작:
  - 포털 켜기/끄기
  - 관리자 설정 비밀번호 확인
  - 이름, 학번, 이메일 입력
  - Brevo API를 통한 토큰 및 가입 링크 발송
  - 해시 전용 신규 토큰은 DB에서 원문을 복구하거나 재표시하지 않으며, 재발송 시 새 수신자 결합 토큰을 발급
- 데이터 저장:
  - `InviteToken`
  - `TokenDistributionLog`
  - 관련 `SystemSetting`
- 관련 관리자 기능:
  - `/admin/settings`의 포털 상태/비밀번호/안내 문구/오늘 발송량
  - `/admin/tokens`의 수동 발송 및 로그
- 회귀 시 주의할 점:
  - 공개 포털은 학생 전용
  - 일일 발송량 제한은 현재 앱 기록 기준 250건
  - `PENDING`, `SENT`, `FAILED` 발송 시도를 함께 세는 서버 측 원자적 일일 한도와 쿨다운을 사용
  - 포털 비밀번호 실패 제한은 keyed 클라이언트/네트워크 키를 사용하고 메모리 키 수를 제한

## 4. 수동 토큰 발송

- 목적: 관리자가 학생, 교사, 방송부, 관리자용 토큰을 직접 메일로 보낼 수 있게 합니다.
- 대상 사용자: 관리자
- 진입 경로: `/admin/tokens`
- 핵심 동작:
  - 이메일 입력
  - 역할 선택
  - 학생 역할일 경우 기수 지정
  - 학생 역할일 경우 유효한 학번도 필수이며 학번의 학년-기수 매핑이 선택한 기수와 일치해야 함
  - 발송 성공/실패 로그 기록
- 데이터 저장:
  - `InviteToken`
  - `TokenDistributionLog`
- 회귀 시 주의할 점:
  - 공개 포털과 수동 발송의 역할 범위가 다름
  - Brevo 실패 시 예약 로그에서 토큰 참조를 분리하고 새 토큰을 같은 트랜잭션에서 삭제하며 실패 시도도 중복 방지와 일일 한도에 포함

## 5. 내 정보와 개인화

- 목적: 로그인한 사용자의 계정 정보와 개인 일정을 제공합니다.
- 대상 사용자: 로그인 사용자
- 진입 경로: `/me`
- 핵심 동작:
  - 사용자 기본 정보 표시
  - 개인 일정 관리
  - 모바일 전용 로그아웃 진입점 제공
  - 비밀번호 변경 후 현재 브라우저도 로그아웃하고 다시 인증
  - 현재 해시와 `sessionVersion`이 조회 이후 그대로일 때만 조건부 갱신하여 동시 관리자 초기화를 덮어쓰지 않음
  - 본인 프로필에서 이름과 이메일만 검증 후 수정할 수 있고 학번은 관리자 관리 필드로 유지
  - 관리자 임시 비밀번호 초기화 후에는 다른 회원 기능보다 비밀번호 변경을 먼저 완료
- 데이터 저장:
  - `User`
  - `PersonalEvent`
- 회귀 시 주의할 점:
  - 개인 일정이 없을 때 홈 문구는 `오늘은 일정이 없습니다.` 기준 유지

## 6. 역할과 접근 변경

- 목적: 가입 후에도 관리자 판단에 따라 계정 역할과 기수를 안전하게 조정합니다.
- 대상 사용자: 관리자, 로그인 사용자
- 진입 경로:
  - 사용자 본인: 로그인 후 적용 결과 사용
  - 관리자: `/admin/users`
- 핵심 동작:
  - 기존 계정을 `STUDENT`, `GRADUATE`, `TEACHER`, `BROADCAST`, `ADMIN`으로 변경
  - 학생, 방송부, 졸업생 계정의 기수 직접 변경
  - 자기 자신 관리자 해제 차단
  - 마지막 관리자 계정 해제/삭제 차단
- 데이터 저장:
  - `User`
  - `SystemLog`
- 관련 관리자 기능: `/admin/users`
- 회귀 시 주의할 점:
  - `GRADUATE`는 로그인은 가능하지만 학생 전용 핵심 정보 접근은 제한
  - 학생 전환 시 `studentId` 4자리 형식과 `gisu` 자동 계산 규칙을 유지
  - 관리자 권한 변경 직후 서버가 DB 기준 최신 역할을 다시 확인해야 함

## 7. 알림

- 목적: 공지, 시스템, 기상곡 상태 등 사용자에게 필요한 알림을 제공합니다.
- 대상 사용자: 로그인 사용자
- 진입 경로: `/notifications`
- 핵심 동작:
  - 알림 목록 조회
  - 읽음 처리
  - 읽은 알림 모두 삭제
  - 헤더/메뉴 배지 갱신
- 데이터 저장: `Notification`
- 관련 관리자 기능: `/admin/notifications`
- 회귀 시 주의할 점:
  - 알림 배지는 공개 셸 사용자 요약과 연동됨
  - 읽은 알림 삭제는 읽지 않은 알림까지 지우면 안 됨

## 8. 오류 신고와 문의 분리

### 오류 신고

- 경로: `/report`
- 목적: 실제 버그나 장애를 신고
- 데이터 저장: `ErrorReport`

### 일반 문의/기능 제안

- 경로: `/help#contact`
- 목적: 문의/제안 안내와 연락 방법 제공
- 현재 기본 안내 채널: `admin@gshs.app`

회귀 시 주의할 점:

- `/report`는 오류 신고 전용 유지
- 일반 문의/제안은 도움말에서 처리

## 8. 권한 모델

현재 주요 역할:

- `STUDENT`
- `GRADUATE`
- `TEACHER`
- `BROADCAST`
- `ADMIN`

역할별 대표 접근:

- 학생: 개인 기능, 기상곡 신청
- 졸업생: 로그인과 기본 계정 기능은 가능하지만 학생 전용 핵심 정보는 제한
- 교사: 링크모음 편집, 공지 작성
- 방송부: 방송부 스튜디오, 기상곡 검수
- 관리자: 운영 도구 전체

권한 관련 회귀 시 특히 확인할 경로:

- `/login`
- `/signup`
- `/signup/request`
- `/me`
- `/notifications`
- `/admin`
- `/music`
